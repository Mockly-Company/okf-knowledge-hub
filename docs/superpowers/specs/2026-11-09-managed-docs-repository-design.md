# 앱이 관리하는 문서 저장소 설계

작성일: 2026-11-09

## 왜 바꾸는가

지금 Documents를 쓰려면 사용자가 로컬 폴더를 고르고, 그 폴더에 저장소를 clone하거나 기존 clone을 연결해야 한다.
폴더를 고르게 하면 사용자는 "문서가 git 저장소로 내려받아진다"는 사실을 알아야 한다. 사용자가 알아야 할 것은 "어느 GitHub 저장소를 문서 저장소로 쓰는가"뿐이다.

AI 화면도 같은 이유로 헷갈린다. "워크스페이스: C:\...", "AGENTS.md: ..." 같은 표시는 무엇을 가리키는지 알기 어렵다.

## 목표

1. 사용자는 자기가 접근할 수 있는 GitHub 저장소 목록에서 문서 저장소를 고르기만 한다. 폴더는 묻지 않는다.
2. 앱이 그 저장소를 앱 데이터 폴더 아래에 clone하고, 앱이 켜져 있는 동안 최신 상태로 유지한다(pull).
3. 프로젝트마다 문서 저장소가 따로 있다. 프로젝트를 바꾸면 Documents와 AI 터미널이 그 프로젝트의 저장소를 쓴다.
4. 문서 수정은 앱 안 AI 터미널에서 한다. 사용자가 AI에게 "PR 올려줘"라고 하면 AI가 브랜치·커밋·푸시·PR을 처리한다.
5. AI 화면은 "터미널에서 열기"만 남기고, 무엇을 대상으로 여는지 사람이 읽을 수 있는 말로 보여 준다.

## 하지 않는 것

- 앱 화면 자체의 문서 편집기에서 커밋·PR을 만드는 기능을 새로 만들지 않는다. 수정과 PR은 AI 터미널의 몫이다.
- 외부 편집기(VS Code 등) 지원을 하지 않는다. 사용자가 앱 폴더를 직접 열어 고치면 커밋·푸시는 본인이 한다.
- 앱이 충돌을 자동으로 병합하지 않는다.
- OKF 형식이 아닌 저장소를 OKF로 바꿔 주지 않는다(기존 초기화 흐름을 이 작업에서 손대지 않는다).

## 실패로 보는 것 (동작은 해도 안 되는 것)

- 사용자에게 로컬 경로를 고르게 하거나, 경로를 알아야만 할 수 있는 일이 남는 것.
- 백그라운드 pull이 AI가 작업 중인 변경을 덮어쓰거나 날리는 것.
- 프로젝트를 바꿨는데 이전 프로젝트의 문서나 터미널 대상이 보이는 것.

## 사용자가 정한 것

- 문서 저장소는 사용 가능한 GitHub 저장소 목록에서 고른다. 앱 폴더에 자동 clone한다.
- 앱의 생명주기에 맞춰 계속 pull해 최신을 보여 준다.
- 프로젝트별로 해당 저장소를 쓴다.
- 문서는 앱 AI 터미널에서만 다루면 된다. 다른 편집기로 다루면 사용자가 알아서 커밋한다.
- 수정 반영은 사람이 앱 AI에게 명령하면 AI가 PR을 올리는 방식이다.
- 고른 저장소가 OKF 형식에 맞지 않으면 막지 않고 경고만 보여 준다.
- AI 화면의 "실행 도구"(요청을 비대화형으로 실행하는 기능)는 없애고 "터미널에서 열기"만 남긴다.
- 사이드바의 "프로젝트 없음 (로컬)"과 닫힌 프로젝트는 숨긴다(PR #20에서 처리 중).
- 연결한 프로젝트 목록과 현재 선택한 프로젝트는 앱 설정(이 컴퓨터)에 저장한다. 문서 저장소에서는 문서만 가져온다.

## 프로젝트 목록의 위치

지금은 연결 목록(`projects`)과 활성 프로젝트(`active_project_id`)가 현재 워크스페이스 저장소의 `.okf/workspace.yml`에 있다(`list_linked_projects`, `link_github_project`, `set_active_github_project`가 `load_workspace_root`로 읽고 쓴다). 프로젝트마다 저장소가 달라지면 이 구조가 성립하지 않는다.

- 연결 목록, 활성 프로젝트, 프로젝트별 문서 저장소를 모두 앱 로컬 설정(`LocalSettingsService`)으로 옮긴다.
- 위 세 명령은 앱 설정을 읽고 쓰도록 바꾼다. 프로젝트 전환은 문서 저장소의 파일을 수정하지 않는다.
- 프로젝트를 전환하면 "현재 워크스페이스"도 그 프로젝트의 문서 저장소로 바뀐다. Documents와 AI 터미널은 지금처럼 현재 워크스페이스를 읽는다.
- 기존 `workspace.yml`의 연결 정보나 예전에 고른 로컬 폴더는 옮기지 않는다. 기존 사용자도 앱에서 프로젝트와 문서 저장소를 다시 연결한다(사용자 결정).
- 다른 컴퓨터에서는 프로젝트를 다시 연결해야 한다(사용자가 받아들인 대가).
- 보드 캐시는 지금처럼 프로젝트별로 둔다. 보드 기능은 문서 저장소의 OKF 여부와 상관없이 동작한다.

## 현재 코드에서 이어받는 것

- 저장소 목록: `list_github_repositories` (`src-tauri/src/commands/workspace.rs`)
- clone: `clone_repository` + 진행률 이벤트 `repository-clone-progress`, 취소 `cancel_repository_clone`. 지금은 `parent_directory`를 사용자에게 받는다.
- 연결·검사: `connect_workspace`, `inspect_workspace` (`.okf/workspace.yml` 검사), `inspect_existing_clone`
- 프로젝트별 저장소 기억: `set_workspace_for_project` / 조회 (`src-tauri/src/settings/service.rs`), 프런트 `ActiveProjectProvider`의 선택 흐름
- 앱 데이터 폴더: `app_data_dir` (`src-tauri/src/settings/commands.rs`)
- AI 터미널 실행 폴더: `connected_workspace_dir` → 현재 연결된 워크스페이스
- PR 생성: `create_draft_pull_request` (`src-tauri/src/github/client.rs`), 지금은 초기화 흐름에서만 쓴다.
- pull 기능은 아직 없다. 새로 만든다(`git2` 사용 중).

## 동작

### 저장소 고르기

- 프로젝트를 선택했는데 그 프로젝트에 문서 저장소가 없으면, Documents 화면에 "문서 저장소 선택"을 보여 준다.
- 목록은 GitHub 저장소 목록이다. 고르면 앱이 `{app_data}/repos/{owner}/{name}`에 clone한다(이미 있으면 재사용). 진행률은 기존 이벤트를 쓴다.
- clone 후 OKF 검사를 하고, 맞지 않으면 "OKF 형식에 맞지 않는 저장소입니다" 경고를 띄우되 연결은 유지한다.
  - 지금 `set_current`/`set_current_for_repository`는 `Ready`가 아니면 거부하므로, OKF가 아니어도 연결할 수 있게 상태를 하나 추가한다(Claude의 판단).
  - 이 경우 Documents는 저장소의 마크다운 파일을 그대로 보여 주고, AI 터미널도 쓸 수 있다. 경고는 Documents 상단에 계속 보인다(Claude의 판단).
- 고른 저장소는 그 프로젝트의 문서 저장소로 기억한다. 설정에서 바꿀 수 있다.

### 최신 유지 (pull)

- 시점: 앱 시작, 프로젝트 전환, 앱이 켜져 있는 동안 주기적으로(간격은 빌더가 정한다, 몇 분 단위).
- 조건: 작업 트리가 깨끗하고 기본 브랜치에 있을 때만 fast-forward로 받는다.
- 조건이 안 맞으면 받지 않고, Documents에 "작업 중인 변경이 있어 최신 내용을 받지 않았습니다"를 보여 준다.
- fast-forward가 안 되면(기본 브랜치가 갈라짐) 받지 않고 같은 방식으로 알린다. 앱이 병합하지 않는다.
- pull 후 Documents 목록과 열린 문서를 다시 읽는다.

### AI 터미널과 PR

- 터미널은 현재 프로젝트의 문서 저장소 폴더에서 연다.
- AI는 문서를 고칠 때 앱이 받아 둔 원본 clone에서 직접 작업하지 않고, 작업마다 git worktree를 만들어 그 안에서 브랜치·커밋·PR을 처리한다(사용자 결정).
  - worktree 위치는 `{app_data}/worktrees/{owner}/{name}/{브랜치}`로 한다(Claude의 판단).
  - `node_modules`처럼 git이 추적하지 않는 큰 폴더는 복사하거나 새로 설치하지 않고, 원본 clone의 폴더를 가리키는 심볼릭 링크로 만들어 디스크를 아낀다(사용자 결정). Windows에서는 관리자 권한 없이 되는 디렉터리 정션(`mklink /J`)을 쓴다(Claude의 판단).
  - 원본 clone은 항상 기본 브랜치이고 수정되지 않은 상태로 남으므로, 앱의 pull이 AI 작업과 부딪히지 않는다.
  - PR이 머지된 worktree는 AI가 다음 세션을 시작할 때 정리한다(`git worktree remove`, `git worktree prune`). 머지 전 worktree는 리뷰 반영을 위해 남긴다(Claude의 판단).
  - 결과: AI가 worktree에서 고친 내용은 PR이 머지되어 pull될 때까지 Documents 화면에 보이지 않는다.
- 터미널 환경에 앱에 로그인된 GitHub 토큰을 넘겨 `git push`와 `gh pr create`가 추가 로그인 없이 되게 한다. (Claude의 판단. 토큰 노출 범위는 이 터미널 프로세스로 한정한다.)
- "원본 clone에서 직접 고치지 말고 worktree를 만들어 작업하고, 추적하지 않는 큰 폴더는 심볼릭 링크로 연결하며, 사용자가 요청하면 PR로 올리고, 머지된 worktree는 정리한다"는 규칙을 앱이 항상 붙이는 고정 규칙으로 넣는다(`compose_rules`). 사용자가 고칠 수 있는 앱 AGENTS.md에는 넣지 않는다. 기존 사용자의 AGENTS.md에도 반드시 적용되어야 하는 안전장치이기 때문이다(Claude의 판단).
- PR이 머지되어 원격 기본 브랜치에 들어오면 다음 pull에서 Documents에 반영된다.

### AI 화면

- "실행 도구" 선택, 요청 입력, 실행/취소, 실행 결과 영역을 없앤다. 백엔드의 비대화형 실행(`run_ai_task` 계열)과 설정의 "명령 템플릿"도 함께 없앤다.
- 남는 것: "터미널에서 열기"(Claude Code, Codex, 사용자 지정)와 터미널 탭.
- 컨텍스트 표시는 경로 대신 사람이 읽을 수 있는 말로 바꾼다.
  - "프로젝트: {이름}"
  - "문서 저장소: {owner}/{name}" (없으면 "문서 저장소를 선택하세요"와 Documents로 가는 링크)
  - "AI 규칙: 앱 기본 규칙 + 저장소 규칙(.okf/AGENTS.md)" 처럼 무엇이 전달되는지 설명. 파일 경로는 보이지 않게 한다.

## 기존 연결 처리 (사용자 결정)

- 기존 사용자도 예외 없이 앱에서 다시 연결한다. 예전 로컬 폴더 연결과 프로젝트별 폴더 기억은 읽지 않는다.
- 설정의 "로컬 폴더 선택"·"기존 clone 연결" UI는 없앤다.

## 빌더에게 맡기는 것

- pull 주기, 실패 재시도 정책.
- `{app_data}/repos` 아래 폴더 이름 규칙(대소문자, 이름 변경된 저장소 처리).
- 저장소 목록 UI의 검색·페이지 처리(기존 컴포넌트 재사용 우선).
- 작업 순서. 다만 AI 화면 정리는 작고 독립적이라 먼저 별도 PR로 내도 된다.
