# 문서 중심 통합 워크스페이스(Workspace) 구조 및 UX 설계

작성일: 2026-11-11

## 1. 해결하려는 문제

기존 화면과 데이터 구조에는 네 가지 핵심 불편이 있었다.

1. **앱의 중심이 불분명함**: 문서 관리 허브임에도 첫 화면(`/`)이 미구현 상태의 `내 작업` 플레이스홀더로 열리고, 로그인조차 `Settings → 외부 연결`로 직접 찾아 들어가야 했다.
2. **Project 없이 문서를 관리할 수 없음**: 문서 저장소 매핑이 `GitHub Project ID`에 종속되어 있어, GitHub Project(칸반 보드)를 쓰지 않는 사용자나 문서 전용 저장소는 아예 연결할 수 없었다(`"프로젝트를 먼저 선택하세요"`).
3. **Project와 Document의 소속 관계가 화면에서 느껴지지 않음**: 사이드바에서는 Project 이름만 드롭다운에 보이고 어떤 문서 저장소가 연결되어 있는지 알 수 없었으며, 메뉴에서도 `Home · Documents · Ticket · Settings · AI`가 평면적으로 섞여 있었다.
4. **연결·전환 과정이 파편화되고 번거로움**: 사이드바 내 비좁은 검색창에서 `검색` 버튼을 수동으로 눌러 Project만 먼저 추가한 뒤, 별도로 `Documents` 탭에 들어가 에러 화면에서 저장소를 다시 골라야 했다.

## 2. 핵심 개념 정리: 무엇이 중심인가

- **앱의 본질과 중심 화면**: **문서(`Documents`)**가 앱의 중심이다. 앱을 열면 기본으로 현재 작업 공간의 문서 화면(`/documents`)으로 진입한다.
- **최상위 작업 단위 = `워크스페이스(HubWorkspace)`**:
  사용자가 전환하며 작업하는 단위는 **문서 저장소(필수 핵심)**와 **GitHub Project 보드(선택 연결)**를 담는 **워크스페이스**다.
  - **방식 A — `Project + 문서 저장소` 워크스페이스**: GitHub Project(칸반·이슈 보드)를 고르고, 그 Project의 기획·명세를 관리하는 문서 저장소를 소속시켜 함께 사용한다. 여러 Project를 등록해 각기 다른(또는 공유하는) 문서 저장소를 연결할 수 있다.
  - **방식 B — `문서 저장소 단독` 워크스페이스**: GitHub Project 없이 문서 저장소만 골라 곧바로 기획·명세 문서를 열람·작성·AI 편집한다. 나중에 칸반 보드가 필요해지면 언제든 기존 워크스페이스에 GitHub Project를 연결할 수 있다.

## 3. 사용자 플로우 및 화면 구조 (UX/UI)

### 3.1 첫 진입 및 워크스페이스 연결 플로우 (`WorkspaceSetupFlow`)
1. **비로그인 상태**: Settings로 떠넘기지 않고 본문 시작 화면에서 곧바로 **GitHub 로그인(Device Flow)**을 진행할 수 있다. 로그인이 완료되면 즉시 워크스페이스 연결 단계로 넘어간다.
2. **통합 워크스페이스 연결 (온보딩 화면 및 `+ 새 워크스페이스 연결` Dialog 공통)**:
   - 열리자마자 로그인된 계정이 접근 가능한 **GitHub Projects**와 **GitHub Repositories** 목록을 자동으로 불러오고 입력 즉시 실시간 필터링한다.
   - 탭으로 두 가지 시작 방식을 명확히 제공한다:
     - **`Project와 함께 시작` (기본)**:
       1. **1단계 — GitHub Project 선택**: 접근 가능한 Project 목록을 즉시 보여 준다(이미 연결된 Project는 구분 표시).
       2. **2단계 — 소속 문서 저장소 선택**: 상단에 방금 고른 Project(`이름 · owner #번호`)를 고정 표시하여 "이 Project에 속할 문서 저장소를 고른다"는 맥락을 분명히 보여 준다. 같은 소유자(`owner/*`) 및 문서 성격(`docs`, `spec`, `knowledge`, `wiki`, `okf`)의 저장소를 상단에 우선 정렬한다. 저장소를 클릭하면 자동 clone 후 워크스페이스 생성·전환을 한 번에 완료한다(`문서 저장소 나중에 연결`도 지원).
     - **`문서 저장소만 관리`**:
       - Project 선택 없이 곧바로 저장소 목록에서 문서 저장소를 골라 자동 clone 및 단독 문서 워크스페이스로 연결한다.

### 3.2 사이드바 위계 (`AppSidebar`)
- **상단: 통합 워크스페이스 스위처 카드**:
  - 단순 드롭다운 대신 카드형 스위처 버튼에 **1행: 워크스페이스 이름(굵게)**, **2행: 소속 문서 저장소(`문서 · owner/repo` 또는 `문서 전용 · owner/repo` / `문서 저장소 연결 필요`)**를 함께 표시해 소속 관계를 항상 드러낸다.
  - 클릭 시 드롭다운 메뉴에서 등록된 모든 워크스페이스(이름 + 연결된 보드·문서 저장소 요약) 간 전환, **`새 워크스페이스 연결`**, **`현재 워크스페이스 설정`**(문서 저장소 변경, Project 보드 연결/변경/해제, 워크스페이스 제거)을 수행한다.
- **중단: 현재 워크스페이스 도구 (`주 메뉴` + `문서 트리`)**:
  - `Documents` (기획·명세 문서 — 활성 시 하단에 `DocumentTree` 표시)
  - `Board` (연결된 GitHub Project 이슈·칸반 보드, `/project`)
  - `AI` (이 문서 저장소 worktree 기반 AI 협업 터미널, `/ai`)
- **하단: 전역 앱 영역**:
  - `Settings` (`/settings`)와 GitHub 계정 상태 영역을 하단에 분리해 워크스페이스 내부 메뉴와 앱 전역 설정의 경계를 명확히 한다.

### 3.3 화면별 맥락 일관성
- **`Documents`**: 상단에 현재 워크스페이스(연결된 Project 또는 `문서 전용`)와 소속 문서 저장소(`owner/repo`) 맥락 및 관리 액션을 표시한다. Project만 있고 문서 저장소가 아직 없으면 해당 Project 이름을 명시해 문서 저장소 연결을 안내한다.
- **`Board` (`ProjectPage`)**:
  - Project가 연결된 워크스페이스면 해당 보드를 표시한다.
  - `문서 전용` 워크스페이스(`project === null`)면 에러나 막연한 문구 대신 **"이 워크스페이스에는 연결된 GitHub Project 보드가 없습니다"** 안내와 **`GitHub Project 보드 연결`** 버튼을 제공해 그 자리에서 보드를 붙일 수 있게 한다.
- **`AI` (`AiPage`)**: 현재 워크스페이스(Project 또는 문서 전용)와 대상 문서 저장소를 사람이 읽기 쉬운 문구로 일관되게 요약한다.

## 4. 데이터 모델 및 하위 호환 (`LocalSettingsService`)

- 로컬 설정 키 `hub-workspaces`(`Vec<HubWorkspace>`), `active-hub-workspace-id`(`String`)를 도입한다.
- `HubWorkspace`: `{ id, title, project: Option<LinkedProject>, docsRepository: Option<DocsRepository> }`
- 기존 `linked-projects` + `project-docs-repositories`(또는 단독 `current-workspace-path`) 데이터가 있으면 첫 조회 시 자동으로 `HubWorkspace` 목록으로 승격·호환한다.
- 워크스페이스 전환 시 `CURRENT_WORKSPACE_PATH_KEY`를 해당 워크스페이스의 관리형 clone 경로로 동기화하여 기존 `Documents` 세션, 백그라운드 `pull`, `AI 터미널` worktree 로직이 수정 없이 그대로 동작하게 한다.
