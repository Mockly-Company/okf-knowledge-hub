# 문서 작성과 리뷰

문서는 편하게 작성하고, 공유와 확정은 필요한 시점에 선택하세요.

로컬 초안을 작성하고, 준비된 변경을 발행하거나 PR로 공유하는 방법을 안내합니다. 자동 저장·검토 요청·발행은 서로 다른 동작입니다.

## 처음 사용할 때

문서 작업은 **Documents**에서 시작합니다. 새 내용을 작성하려면 `새 문서`, 기존 내용을 고치려면 문서를 연 뒤 `편집`을 선택하세요.

작업 중에는 세 가지 내용을 구분하면 됩니다.

| 구분 | 의미 | 다른 사람에게 보이는가? |
| --- | --- | --- |
| 로컬 초안 | 내 기기에서 작성 중인 내용 | 자동 저장만으로는 공유되지 않음 |
| 검토 요청 | GitHub PR로 공유한 변경 제안 | PR에 접근할 수 있는 사람이 확인 가능 |
| 확정본 | 발행해 기본 브랜치에 반영한 문서 | 저장소의 확정 문서로 제공 |

**자동 저장은 발행이 아닙니다. 검토 요청도 발행이 아닙니다.** 검토 승인 역시 확정본을 자동으로 변경하지 않습니다.

## 새 문서 작성하기

1. Documents 목록에서 `새 문서`를 누릅니다. 왼쪽 문서 트리의 폴더에서 시작할 수도 있습니다.
2. **제목**, **저장 폴더**, **템플릿**을 확인합니다. 파일명은 제목으로 자동 생성됩니다.
3. 템플릿 미리보기를 확인한 뒤 `문서 만들기`를 누릅니다. 내장 템플릿의 작성 예시는 참고용이며, 예시 내용이 새 문서에 그대로 들어가지는 않습니다.
4. 문서 본문을 작성합니다. 필요한 경우 `Markdown 원문`으로 전환해 문법을 직접 수정합니다.
5. 지금 마무리하지 않아도 됩니다. `편집 종료`를 선택하면 초안을 유지한 채 문서 화면으로 돌아갑니다.

같은 파일명이 이미 있으면 숫자를 붙여 구분하며 기존 문서를 덮어쓰지 않습니다. 새 폴더는 문서를 만들기 전까지 생성 예정 경로로 표시됩니다.

## 기존 문서 편집하기

1. 목록이나 문서 트리에서 문서를 엽니다.
2. 문서 상세에서 `편집`을 누릅니다. 작성 중이던 초안이 있으면 이어서 작업합니다.
3. `문서 편집`과 `Markdown 원문` 중 편한 방식을 선택합니다. 두 화면은 서로 다른 문서가 아니라 같은 작성 내용의 편집 방식입니다.
4. 잠시 멈추려면 `편집 종료`를 누릅니다. 이 동작은 변경 내용을 버리지 않습니다.

지원 범위 밖의 Markdown이 포함된 경우 원문 모드로 편집할 수 있습니다. 원문 모드가 보인다는 이유만으로 문서가 잘못된 것은 아닙니다.

### 자동 저장 상태 확인

| 표시 | 의미와 할 일 |
| --- | --- |
| 자동 저장 대기중 | 입력 내용을 저장하기 전입니다. 잠시 기다리세요. |
| 로컬에 저장중 | 내 기기에 기록 중입니다. |
| 로컬에 자동 저장 완료 | 로컬 초안 저장이 끝났습니다. 원격 공유나 발행은 별도입니다. |
| 로컬 저장 실패 | 오류 안내를 확인하고 다시 시도하세요. 저장 완료를 확인하기 전까지 작성 내용을 유지하세요. |
| 외부 변경 감지 | 다른 프로그램에서 같은 파일이 바뀌었습니다. 두 내용을 확인한 뒤 사용할 내용을 선택하세요. |

외부 변경을 처리할 때는 디스크 내용 사용, Hub 내용 사용 또는 직접 병합 중 상황에 맞는 방법을 선택합니다. 비교하지 않고 한쪽을 선택하면 필요한 변경을 놓칠 수 있습니다.

## 변경을 확인하고 발행하기

1. 편집 화면에서 `발행`을 누릅니다. 이 버튼을 누르는 즉시 확정본이 바뀌지는 않습니다.
2. 확인 화면의 `원문 비교`에서 추가·삭제된 줄을 확인합니다. 문서별 제목을 눌러 비교 내용을 접거나 펼칠 수 있습니다.
3. 읽는 모습도 확인하려면 `문서 미리보기`로 전환합니다.
4. 새 수정 커밋이 필요한 경우 **변경 설명**을 작성합니다. 변경 설명은 Git 커밋 메시지에 사용됩니다.
5. **바로 발행** 또는 **검토 요청**을 선택하고 최종 버튼을 누릅니다.

| 선택 | 결과 |
| --- | --- |
| 바로 발행 → 발행하기 | 현재 문서를 확정본에 반영합니다. 저장소의 권한·보호 규칙을 통과해야 합니다. |
| 검토 요청 → 검토 요청 보내기 | 현재 변경안을 PR로 공유합니다. 확정본은 바뀌지 않습니다. |

현재 문서만 대상으로 처리하며 다른 문서의 초안을 함께 발행하지 않습니다. 처리 후에는 해당 문서 화면으로 돌아갑니다. 확인 중 수정할 부분을 찾았다면 `작성으로 돌아가기`를 선택하세요.

### 변경 설명 작성 예시

예시 문서인 **지도 검색 API 계약**에서는 위치 권한이 없는 사용자도 검색할 수 있도록 좌표 입력 조건을 변경합니다. 변경 설명에는 단순히 “문서 수정”보다 변경한 목적을 적는 편이 좋습니다.

> 위치 권한 없이 장소를 검색할 수 있도록 API 계약 보완

## 검토 요청 보내기

발행 확인 화면에서 `검토 요청`을 선택하면 **검토 요청 메모**를 작성할 수 있습니다. 이 메모는 PR 설명에 대응하며, 변경 설명과는 목적이 다릅니다.

- **변경 설명:** 이번에 무엇을 바꿨는지 기록합니다.
- **검토 요청 메모:** 왜 바꿨고 무엇을 검토해주면 되는지 전달합니다.

API 계약 예시의 검토 요청 메모는 다음처럼 작성할 수 있습니다.

> 위치 권한이 없는 사용자도 장소를 검색할 수 있도록 좌표를 선택 입력으로 변경했습니다. 좌표를 전달하는 기존 요청의 거리순 정렬은 유지합니다. 좌표 쌍 검증, 위치 없는 요청의 관련도순 정렬, distanceMeters의 null 처리 기준을 중심으로 검토 부탁드립니다.

검토·승인은 기본적으로 선택 과정입니다. 다만 저장소가 필수 승인이나 검사를 요구하면 해당 조건을 통과해야 발행할 수 있습니다.

### 수정본을 다시 공유할 때

| 연결된 PR | 다음 검토 요청의 처리 |
| --- | --- |
| 아직 열려 있음 | 같은 PR에 수정 커밋을 추가합니다. 새 PR을 만들지 않습니다. |
| 이미 병합됨 | 확정본을 다시 편집한 새 작업으로 취급하고 새 PR을 만듭니다. |
| 병합 없이 닫힘 | 새 PR을 만드는 사실을 확인한 뒤 검토를 요청합니다. 닫힌 PR을 자동으로 다시 열지 않습니다. |

기존 PR을 갱신할 때는 현재 PR 설명을 불러오는 것이 기준입니다. 설명을 바꾸지 않았다면 그대로 유지하며, 수정했다면 다른 사람의 후속 변경을 덮어쓰지 않도록 확인합니다.

## 문서 리뷰하기

1. 문서 상세의 PR 상태 옆에서 `리뷰 보기`를 누릅니다.
2. `제안 문서`에서 변경 후 내용을 읽고, `변경 비교`에서 확정본과의 차이를 확인합니다. 리뷰 대상은 내 기기의 미공유 초안이 아니라 PR에 공유한 수정본입니다.
3. 오른쪽 **리뷰** 패널에서 요청자의 메모와 리뷰 기록을 읽습니다. 좁은 화면에서는 `리뷰 열기`로 패널을 엽니다.
4. 리뷰 의견과 검토 결과를 선택하고 `리뷰 제출`을 누릅니다.
5. 확인을 마치면 `문서로 돌아가기`로 같은 문서 상세에 복귀합니다.

패널의 왼쪽 경계를 드래그해 너비를 조절할 수 있습니다. 경계에 키보드 포커스를 둔 뒤 왼쪽·오른쪽 방향키로도 조절할 수 있으며, 선택한 너비는 이 기기에 저장됩니다.

### 의견·승인·수정 요청의 차이

| 검토 결과 | 언제 쓰는가? | 효과 |
| --- | --- | --- |
| 의견 남기기 | 질문, 참고 사항, 개선 제안을 전달할 때 | 승인이나 수정 요청으로 간주하지 않음 |
| 승인 | 검토한 수정본에 동의할 때 | 승인 기록을 남김. 자동 발행하지 않음 |
| 수정 요청 | 반영 전에 해결해야 할 사항이 있을 때 | 수정 요청 기록을 남김. 필요한 수정 이유를 작성 |

일반 댓글을 달았다는 이유만으로 `수정 요청됨`이 되지는 않습니다. 수정 요청은 별도의 검토 결과입니다. 요청자는 자신의 PR에 의견을 남길 수 있지만 자기 PR을 승인하거나 수정 요청할 수는 없습니다.

수정 요청은 “수정해주세요”보다 대상과 완료 기준을 구체적으로 적어주세요.

> 좌표를 생략한 응답에서 distanceMeters가 null인 경우의 계약 테스트를 추가해주세요. 기존 클라이언트가 숫자로만 처리하는 경로가 없는지 웹·데스크톱 검증 결과를 확인한 뒤 다시 검토하겠습니다.

## 검토 상태 읽기

| 상태 | 의미 | 다음 행동 |
| --- | --- | --- |
| 검토 대기중 | 공유한 변경안의 검토 결과를 기다리는 상태 | 제안 문서와 의견 확인 |
| 수정 요청됨 | 검토자가 수정 요청을 제출한 상태 | 요청 사항을 수정하고 같은 PR에 공유한 뒤 재검토 요청 |
| 검토 승인됨 | 검토한 버전에 승인 기록이 있는 상태 | 최신 수정본의 검토 여부와 발행 제한 확인 |
| 검토 종료 | PR이 병합 없이 닫힌 상태 | 필요하면 새 검토 요청 시작 |
| 발행 완료 | PR의 변경이 확정본에 반영된 상태 | 다시 수정할 때는 새 초안 시작 |

다음 표시는 PR의 검토 결과와 구분해 확인하세요.

- **미공유 변경 있음:** 내 로컬 초안이 PR에 공유한 내용과 다릅니다. 검토자에게는 아직 보이지 않습니다.
- **재검토 필요:** 이전 승인 이후 검토 대상이 바뀌었습니다. 기존 승인 표시만으로 새 수정본까지 검토됐다고 판단하지 마세요.
- **발행 제한 안내:** 필수 검사가 진행 중이거나 실패했거나, 충돌·권한 문제가 있을 수 있습니다. 승인 상태와 별개로 안내된 조건을 해결해야 합니다.

수정본을 공유했다고 기존 수정 요청이 자동으로 해제되지는 않습니다. 또한 승인만으로 자동 발행하지 않습니다. 작성자가 발행을 선택하고 최신 권한·보호 규칙을 통과해야 확정본이 바뀝니다.

## 변경 취소와 초안 복구

나중에 이어 쓸 예정이라면 `변경 취소`가 아니라 **편집 종료**를 선택하세요.

1. 작성 내용을 버리려면 `변경 취소`를 누릅니다.
2. 확인창에서 결과를 확인하고 `변경 버리기`를 선택합니다. 계속 작성하려면 `계속 편집`을 누릅니다.
3. 기존 문서는 마지막 확정본으로 돌아가고, 미발행 새 문서는 제거된 뒤 문서 목록으로 돌아갑니다.
4. 바로 되돌리려면 완료 토스트의 `실행 취소`를 누릅니다.
5. 나중에 복구하려면 Documents의 `최근 삭제한 초안`에서 해당 항목의 `초안 복구`를 선택합니다.

버린 내용은 **7일간** 복구할 수 있으며, 만료된 항목은 복구 대상으로 제공하지 않습니다. 로컬 변경을 취소해도 이미 PR에 공유한 내용이나 PR 자체는 삭제되지 않습니다.
