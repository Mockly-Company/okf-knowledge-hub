# AGENTS.md — OkHub 워크스페이스 작업 규칙

이 파일은 현재 선택된 OkHub 워크스페이스에서 AI 에이전트가 따르는 공유 규칙이다.
특정 프로젝트나 저장소 이름을 하드코딩하지 않고, **항상 현재 선택된 프로젝트(`HubWorkspace`)와 `.okf/workspace.yml`에 연결된 문서 저장소 · 코드 저장소**를 기준으로 반영한다.

## 0. 선택된 프로젝트 · 저장소 자동 반영 원칙

- 내장 터미널 실행 시 앱이 함께 주입하는 **`현재 선택된 프로젝트 · 저장소 컨텍스트`** 섹션(활성 GitHub Project, 문서 저장소, 연결 코드 저장소)을 최우선 기준으로 사용한다.
- 외부 단독 실행 시에는 `.okf/workspace.yml`의 `github.active_project_id` / `github.projects` 및 `repositories` 정의를 읽는다.
- `[기획]`·문서 작업은 **선택된 문서 저장소**의 worktree와 PR에, `[디자인]`·`[백엔드]`·`[프론트엔드]` 구현 작업은 **연결된 코드 저장소**의 worktree와 PR(`Closes #<이슈번호>`)에, 백로그 생성과 상태 변경은 **선택된 GitHub Project**에 반영한다.

## 1. 문서 2벌 원칙 (`.md` = AI 원본 / `.html` = 사람용 뷰)

- **AI는 `.md`만 읽고 수정한다**: 모든 지식의 유일한 원본은 `docs/**/*.md`이며, AI는 `.html`을 역파싱하지 않는다.
- **사람을 위해 동반 `.html`을 항상 함께 생성·갱신한다**: 예약 파일(`index.md`, `log.md`, `README.md`)을 제외한 일반 문서를 작성·수정할 때는 같은 이름의 `<문서명>.html`을 표준 골격(`.okf/templates/human-view.html` + `docs/_assets/okf-doc.css`)으로 함께 생성·갱신한다.

## 2. 이번 PR 변경점 표시 · 교체 규칙 (`Reset → Mark`)

기획 PR을 올릴 때는 매번 **"이전 PR의 변경 표시는 모두 지우고, 이번 PR에서 달라진 부분만 새로 표시"**한다.

1. **이전 표시 제거 (`Reset`)**: 기존 문서를 수정하기 전 `.md`의 이전 `[NEW]`·`[CHANGED]` 말머리와 `.html`의 이전 `.is-new`·`.is-changed` 강조·배지를 모두 제거해 일반 본문으로 만든다.
2. **이번 변경만 표시 (`Mark`)**: `.md`의 `## 이번 변경 요약` 및 변경 항목(`[NEW]`/`[CHANGED]`), `.html`의 `.change-banner` 및 변경 카드(`.is-new`/`.is-changed`), PR 본문의 `## 이번 PR에서 달라진 점`에만 최신 변경점을 표시한다.

## 3. 영역별 연쇄 백로그 자동 파생 · 수행 규칙 (`[기획]`·`[디자인]` → `[백엔드]`·`[프론트엔드]`)

- **초기 등록**: 새 기능(`Epic`)을 시작할 때는 먼저 **`[기획]`(`layer:planning`)** 과 **`[디자인]`(`layer:design`)** 백로그를 우선 등록해 수행한다.
- **`[기획]` 완수 즉시**: 확정된 `.md`를 근거로 선택된 프로젝트의 같은 Epic 아래에 **`[백엔드]`(`layer:backend`) + `[프론트엔드]`(`layer:frontend`)** 하위 작업(Sub-issues, `이전 단계: #<기획이슈>`)을 자동으로 생성한다.
- **`[디자인]` 완수 즉시**: 확정된 디자인 산출물을 근거로 같은 Epic 아래에 **`[프론트엔드]`(`layer:frontend`)** 하위 작업(`이전 단계: #<디자인이슈>`)을 자동으로 생성·보강한다.
- **자율 연쇄 수행**: 상위 완료로 선행 조건이 풀린(`Ready`) `[백엔드]` → `[프론트엔드]` 백로그는 대상 코드 저장소의 격리 `git worktree`에서 구현·검증·PR(`Closes #<이슈번호>`) 생성까지 이어서 수행한다.

## 4. 이슈 및 안전 규칙

- GitHub Project 공통 필드:
  - `Status`: `Backlog` → `Ready` → `In progress` → `In review` → `Done`
  - `영역`: `기획` / `디자인` / `프론트엔드` / `백엔드`
  - `타입`: `기능`(Epic) / `작업`(Sub-issue, Draft Issue 사용 금지)
  - `Priority`: `P0`(즉시) ~ `P3`(낮음), 선행 관계는 본문 `이전 단계: #N` 표기
- 원격 `merge`, 영구 삭제는 사용자 승인 범위를 따르며(위임된 자율 세션에서는 검증 통과 후 머지·후속 파생까지 연속 수행), 토큰·비밀번호는 어떤 파일에도 기록하지 않는다.
