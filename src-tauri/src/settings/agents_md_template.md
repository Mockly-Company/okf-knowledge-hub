# AGENTS.md — OkHub 워크스페이스 작업 규칙

이 파일은 현재 선택된 OkHub 워크스페이스에서 AI 에이전트가 따르는 공유 규칙이다.
특정 프로젝트나 저장소 이름을 하드코딩하지 않고, **항상 현재 선택된 프로젝트(`HubWorkspace`)와 `.okf/workspace.yml`에 연결된 문서 저장소 · 코드 저장소**를 기준으로 반영한다.

> **절대 규칙 — OkHub는 코드 구현을 하지 않는다**
> OkHub 워크스페이스의 AI는 **아이디어 → 기획 문서(PRD · 화면명세서 · 정책서) 작성 → 기획자(`[기획]`)·디자이너(`[디자인]`)·개발자(`[백엔드]`, `[프론트엔드]`) 백로그 수립 → 그중 `[기획]`·`[디자인]` 백로그까지만 자율 수행해 문서를 완성**한다.
> **`[백엔드]`·`[프론트엔드]` 실제 코드 구현 및 코드 저장소 구현 PR 생성은 절대 수행하지 않으며**, 개발자가 바로 착수할 수 있도록 문서 링크와 완료 조건이 정리된 백로그 상태로 남겨 둔다.

## 0. 선택된 프로젝트 · 저장소 자동 반영 원칙

- 내장 터미널 실행 시 앱이 함께 주입하는 **`현재 선택된 프로젝트 · 저장소 컨텍스트`** 섹션(활성 GitHub Project, 문서 저장소, 연결 코드 저장소)을 최우선 기준으로 사용한다.
- 외부 단독 실행 시에는 `.okf/workspace.yml`의 `github.active_project_id` / `github.projects` 및 `repositories` 정의를 읽는다.
- **`[기획]` · `[디자인]` 문서 작업**: **선택된 문서 저장소**의 격리 worktree에서 PRD·기획서·화면명세서(`.md` + `.html`)를 작성·갱신하고 **문서 저장소 PR**(`Closes #<이슈번호>`)로 올린다.
- **연결된 코드 저장소 활용 범위**: 기존 코드 맥락 파악을 위한 **읽기 전용 참조**와 **`[백엔드]`·`[프론트엔드]` 개발자 백로그 이슈 등록 대상**으로만 쓰며, 코드를 직접 수정하지 않는다.
- **백로그 및 상태 반영**: 모든 Epic/Sub-issue 생성과 `Status`·`영역`·`Priority` 변경은 **선택된 GitHub Project**에 반영한다.

## 1. 아이디어 → PRD · 화면명세서 및 문서 2벌 원칙 (`.md` = AI 원본 / `.html` = 사람용 뷰)

- **아이디어 구체화 산출물**: 아이디어를 받으면 기능 성격에 맞춰 **기획서/PRD**(`.okf/templates/product-spec.md`), **화면명세서**(`.okf/templates/screen-spec.md`), **설계/결정 기록**(`.okf/templates/design-doc.md`, `decision-record.md`)을 작성한다.
- **AI는 `.md`만 읽고 수정한다**: 모든 지식의 유일한 원본은 `docs/**/*.md`이며, AI는 `.html`을 역파싱하지 않는다.
- **사람을 위해 동반 `.html`을 항상 함께 생성·갱신한다**: 예약 파일(`index.md`, `log.md`, `README.md`)을 제외한 일반 문서를 작성·수정할 때는 같은 이름의 `<문서명>.html`을 표준 골격(`.okf/templates/human-view.html` + `docs/_assets/okf-doc.css`)으로 함께 생성·갱신한다.

## 2. 이번 PR 변경점 표시 · 교체 규칙 (`Reset → Mark`)

기획·디자인 문서 PR을 올릴 때는 매번 **"이전 PR의 변경 표시는 모두 지우고, 이번 PR에서 달라진 부분만 새로 표시"**한다.

1. **이전 표시 제거 (`Reset`)**: 기존 문서를 수정하기 전 `.md`의 이전 `[NEW]`·`[CHANGED]` 말머리와 `.html`의 이전 `.is-new`·`.is-changed` 강조·배지를 모두 제거해 일반 본문으로 만든다.
2. **이번 변경만 표시 (`Mark`)**: `.md`의 `## 이번 변경 요약` 및 변경 항목(`[NEW]`/`[CHANGED]`), `.html`의 `.change-banner` 및 변경 카드(`.is-new`/`.is-changed`), PR 본문의 `## 이번 PR에서 달라진 점`에만 최신 변경점을 표시한다.

## 3. 직군별 백로그 작성 및 `[기획]`·`[디자인]` 자율 수행 경계

1. **직군별 전체 백로그 수립 (`기획자` · `디자이너` · `개발자`)**
   - 아이디어나 신규 기능(`Epic`)을 정리할 때는 선택된 GitHub Project에 **`[기획]`(`layer:planning`), `[디자인]`(`layer:design`), `[백엔드]`(`layer:backend`), `[프론트엔드]`(`layer:frontend`)** 백로그를 역할과 선행 순서(`이전 단계: #N`)에 맞게 작성한다.
2. **`[기획]` 백로그 자율 완수 → PRD 완성 및 하위 백로그 정교화**
   - AI는 `[기획]` 이슈를 수행해 PRD·정책 문서(`.md` + `.html`)를 완성하고, 확정된 명세를 바탕으로 같은 Epic 아래에 `[디자인]`(화면명세서) 및 `[백엔드]`·`[프론트엔드]` 개발 백로그(Sub-issues, `이전 단계: #<기획이슈>`, 참조 문서 경로)를 생성·갱신한다.
3. **`[디자인]` 백로그 자율 완수 → 화면명세서 완성 및 프론트 백로그 보강**
   - AI는 `[디자인]` 이슈를 수행해 화면 구성·상태별 UI·인터랙션이 담긴 **화면명세서**(`.md` + `.html`)를 완성하고, 같은 Epic 아래의 `[프론트엔드]` 개발 백로그(`이전 단계: #<디자인이슈>`)에 화면명세서 링크와 완료 조건을 보강한다.
4. **개발자 백로그(`[백엔드]` · `[프론트엔드]`)에서 정지 (코드 구현 금지)**
   - `[기획]`·`[디자인]` 문서 PR 제출과 개발자 백로그 정리가 끝나면 작업을 완료한다. **`[백엔드]`·`[프론트엔드]` 이슈의 실제 코딩·구현 PR은 수행하지 않고 개발자에게 핸드오프한다.**

## 4. 이슈 및 안전 규칙

- GitHub Project 공통 필드:
  - `Status`: `Backlog` → `Ready` → `In progress` → `In review` → `Done`
  - `영역`: `기획` / `디자인` / `프론트엔드` / `백엔드`
  - `타입`: `기능`(Epic) / `작업`(Sub-issue, Draft Issue 사용 금지)
  - `Priority`: `P0`(즉시) ~ `P3`(낮음), 선행 관계는 본문 `이전 단계: #N` 표기
- 원격 `merge`, 영구 삭제는 사용자 승인 범위를 따르며(위임된 자율 세션에서는 `[기획]`·`[디자인]` 문서 PR 검증·머지 및 개발자 백로그 등록까지만 연속 수행), 토큰·비밀번호는 어떤 파일에도 기록하지 않는다.
