# AGENTS.md — OkHub 워크스페이스 작업 규칙

이 파일은 이 워크스페이스에서 AI 에이전트가 따르는 공유 규칙이다.
프로젝트별 특이사항은 아래 섹션에 추가하고, 공통 규칙은 바꾸지 않는다.

## 1. 컨텍스트 읽기

- `.okf/workspace.yml`: 워크스페이스 정의(문서 루트, 연결 코드 저장소, GitHub Project).
- `docs/`: 확정 문서(기본 브랜치 기준). 기획서·설계·결정 기록은 여기서 찾는다.
- GitHub Project: 진행판. Issue와 PR이 실제 작업 데이터이며, 보드는 그 투영이다.

## 2. 이슈 규칙 (GitHub Project)

- Status: `Backlog` → `Ready` → `In progress` → `In review` → `Done`
- 영역: `기획` / `디자인` / `프론트엔드` / `백엔드` (Project `영역` 필드, 없으면 이슈 라벨 `layer:*`로 판단)
- 타입: `기능`(Epic급) / `작업`(실행 단위) (Project `타입` 필드)
- 우선순위: `P0`(즉시) ~ `P3`(낮음)
- 계층은 sub-issue로: Epic → Story → Task. Draft issue는 공유 원본으로 쓰지 않는다.
- 선행 관계는 이슈 본문에 `이전 단계: #N` 한 줄로 남긴다.
- 이슈를 만들 때는 영역·타입·Status를 항상 지정하고, 관련 문서가 있으면 본문에 경로를 적는다.

## 3. 기획서·문서 규칙

- 새 문서는 `docs/` 아래 주제 경로에 Markdown으로 만든다.
- 확정 문서를 직접 고치지 않고, 먼저 초안을 만들고 변경 이유를 함께 적는다.
- API 계약은 문서에 스키마를 복붙하지 않고 `operationId`로 참조한다(있는 경우).

## 4. 확인이 필요한 동작

- `push`, `merge`, 삭제, Issue 종료, Project 삭제는 실행 전에 사용자에게 확인받는다.
- 토큰·비밀번호를 파일에 기록하지 않는다. 인증은 Hub의 GitHub 연결을 따른다.
